Huffman coding is a lossless compression method. It examines the frequency of every character in a document and gives common characters shorter codes. Spaces, vowels, and frequently repeated letters usually receive short codes, while uncommon letters and punctuation receive longer codes. The decoder uses the same code table to reconstruct the original document exactly.

This paragraph is intentionally repetitive because repetition is useful when testing compression. Compression should reduce the size of data without changing its meaning or its bytes. A successful round trip begins with the original text, creates a frequency table, builds a Huffman tree, generates prefix-free codes, encodes the text into bits, writes a header, and stores the packed bits in a binary file. Decompression reads the header, rebuilds the code table, unpacks the bits, and decodes the original characters.

The compressor must preserve every important detail. It must preserve spaces, new lines, commas, periods, colons, semicolons, quotation marks, parentheses, and numbers. It must preserve upper-case letters and lower-case letters as different characters. The letter A is not the same as the letter a. The character 0 is not the same as the character O. These small differences are important when checking whether the decompressed text matches the input exactly.

Numbers can appear in the input too: 0123456789, 1234567890, 42, 100, 2026, and 65535. Punctuation can appear as well: ! ? . , : ; - _ ( ) [ ] { } / \\ ' " @ # $ % & * + =. The compressor should treat each of these symbols as ordinary characters and should reproduce them after decompression.

A binary file is not a text file, so the header must be written and read carefully. The number of codes tells the decoder how many records to read. Each record contains one character, the length of its Huffman code, and the code itself. Because code lengths vary, the decoder needs the length before it can safely read the code. After the code table, the file stores the number of packed bytes and the number of valid bits in the final byte.

Testing should include short documents and long documents. It should include documents with one repeated character, documents with many different characters, and documents with an uneven frequency distribution. A file containing mostly spaces and the letter e should compress differently from a file containing random characters. A file with very little repetition may not become smaller because the header can be larger than the savings from the encoded data.

The most important test is exact equality. After compression and decompression, the resulting text should equal the original text character for character. The output should contain the same number of lines, the same spaces, the same punctuation, and the same final newline.
